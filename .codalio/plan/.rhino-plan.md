# Implementation Plan: SnapDo

## Summary
SnapDo is an ultra-minimalist task management application offering sub-second capture via instant text input and hands-free Siri / Google Assistant voice integration. Built on Rhino on Rails, it features fluid gesture triage, OLED dark mode, offline queuing, and real-time telemetry.

## PRD gaps compensated
- **PROTECTED_ROUTE_NO_AUTH_AC**: Added explicit route gating and permission checks for settings, focus, upcoming, and archive screens.
- **SITEMAP_PAGE_NO_AC**: Added AC-12 and component mapping for `/api/v1/voice-capture` route.

## Models (reference)

### Task
- Ownership: organization-scoped
- Key fields: title, description, status, due_at, completed_at, raw_transcript, source
- Relationships: belongs_to Organization

### UserSetting
- Ownership: organization-scoped
- Key fields: theme, font_scale, haptic_intensity, auto_archive_days, quick_add_shortcut_enabled, sound_effects_enabled
- Relationships: belongs_to Organization

### VoiceIntegration
- Ownership: organization-scoped
- Key fields: provider, enabled, shortcut_phrase, last_synced_at
- Relationships: belongs_to Organization

### VoiceCommandLog
- Ownership: organization-scoped
- Key fields: provider, utterance, parsed_action, confidence, outcome
- Relationships: belongs_to Organization

## Extras (NOT covered by blueprint — develop stage implements these by hand)

- **Voice Capture API Webhook Endpoint** (`POST /api/v1/voice-capture`)
  - **Rule**: Accepts JSON payloads from Siri / Google Assistant shortcuts, parses text & natural language dates, creates a Task, and writes a VoiceCommandLog entry.
  - **Where code lives**: `server/app/controllers/api/v1/voice_captures_controller.rb`
  - **Acceptance criterion**: AC-9 & AC-10 (Siri & Google Assistant voice task payload execution)

- **Natural Language Date Parser**
  - **Rule**: Intercepts task creation payloads containing date strings (e.g., "tomorrow at 5pm") and parses them into `due_at` timestamps.
  - **Where code lives**: `server/app/models/concerns/natural_language_date_parser.rb`
  - **Acceptance criterion**: AC-8

## Implementation order (recommended stage flow)

1. **Plan** — Complete blueprint YAMLs, ui-handoff.json, acceptance-criteria.json, and index.json.
2. **Develop** — Phase A: Run `bundle exec rails rhino:blueprint` and apply migrations. Phase B: Implement `VoiceCapturesController` and policy extras. Phase D: Add backend unit/integration tests.
3. **UI / UI-Integration** — Scaffold page components and wire design prototype JSX with `@rhino-dev/rhino-react` hooks inside `AppOwnerProvider`.
4. **Test** — Execute `bundle exec rails test` to ensure clean backend tests.
5. **Review** — Verify PRD compliance and final test reports.
